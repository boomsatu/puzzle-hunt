🎯 Modulo Zero — Pembagian Sempurna

Konsep inti: setiap ronde harus memproses jumlah key yang membagi habis keyspace tanpa sisa

Mengapa Modulo 0 Penting?

Jika keyspace tidak habis dibagi window size, akan ada "celah" kecil di akhir rentang yang tidak pernah diperiksa — key yang tersembunyi di celah itu tidak akan pernah ditemukan. Dengan jaminan modulo 0, setiap key dalam keyspace pasti akan tercakup.

// Contoh Puzzle #71 (71-bit)
Keyspace = 2⁷⁰ = 1,180,591,620,717,411,303,424
Window = 2³⁰ = 1,073,741,824

// Pembagian:
2⁷⁰ ÷ 2³⁰ = 2⁴⁰ = 1,099,511,627,776 windows
// Sisa pembagian:
2⁷⁰ mod 2³⁰ = 0 ✅ Sempurna!

// GPU: 16 workers × 2³⁰ per round
Keys/round = 16 × 2³⁰ = 2³⁴ = 17,179,869,184
2⁷⁰ ÷ 2³⁴ = 2³⁶ = 68,719,476,736 rounds
2⁷⁰ mod 2³⁴ = 0 ✅ Sempurna!
✅

Double Guarantee

1. Standard Puzzles: Keyspace = 2^(N-1), window = 2³⁰ → selalu habis dibagi karena keduanya power-of-2.
2. Custom Puzzles: Auto-Padding menambah key ke batas akhir agar total habis dibagi window size → sisa 0 terjamin.

CUDA Time-Slicing

16 worker processes dikirim ke GPU secara paralel, tapi CUDA driver men-serialize mereka via time-slicing — hanya 1 solver aktif di GPU per waktu. Ini memberikan full compute power per window tanpa resource contention, sambil tetap mendapatkan 16 posisi jump berbeda per ronde.

🔧 CUDA Compilation — Blackwell sm_120

Instruksi kompilasi solver CUDA untuk arsitektur Blackwell

⚠️

Blackwell Membutuhkan CUDA 12.8+

RTX PRO 6000 Blackwell menggunakan Compute Capability 12.0 (sm_120). Binary solver yang dikompilasi untuk sm_86 (Ampere) atau sm_89 (Ada) akan gagal dengan error invalid device symbol.

# Verifikasi CUDA Toolkit
nvcc --version # Harus >= 12.8

# Compile cuBitCrack untuk Blackwell
cmake -DCUDA_NVCC_FLAGS="-gencode arch=compute_120,code=sm_120" ..
make -j$(nproc)

# Optimal runtime parameters untuk 188 SMs
cuBitCrack -b 188 -t 256 -p 256 -e -c \
    <target_address> --keyspace <start>:<end>

# Kangaroo CUDA (JeanLucPons)
kangaroo -gpu -gpuId 0 -d 18 input.txt

🎲 Strategi: Scan Awal → Random Jump

Konsep pick_window_smart() — wajib scan range awal terlebih dahulu, baru random jump

📍 Phase 1: Sequential Start

Ronde-ronde awal wajib memindai dari posisi 0% (range start). Ini memastikan key yang berada di awal keyspace tidak terlewat. Jumlah window prioritas = num_workers pertama dari keyspace.

Window #1: 0x80000...00000000 → 0.00%
Window #2: 0x80000...40000000 → 0.00%
Window #3: 0x80000...80000000 → 0.00%
... sequential sweep ...

🎲 Phase 2: Random Jump

Setelah range awal di-sweep, sistem beralih ke random jump — memilih window secara acak dari seluruh keyspace yang belum dipindai. Dengan 16 workers, ada 16 posisi random per ronde.

Window #9: 0xb3982e... → 40.31%
Window #10: 0xddfc22... → 73.43%
Window #11: 0xbcb6a0... → 47.43%
... random positions ...
